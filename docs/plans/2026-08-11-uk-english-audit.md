# Plan: UK English compliance audit

## Goal

Verify that all schema, UI, documentation, code identifiers, comments, and configuration in the codebase use UK English spelling and terminology as required by `.cursor/rules/uk_english.mdc`.

## Background

The project has an established UK English rule (`.cursor/rules/uk_english.mdc`) requiring:
- UK spellings (licence not license, colour not color, etc.)
- UK-English field names in owned schema (time_zone, height_m with metres)
- UK English in all documentation, comments, and identifiers
- Exception: established library/API identifiers that cannot change (e.g. Python's stdlib `timezone`)

## Scope

### In scope

- **Code review**: Search for common US English patterns in Python source files (function names, variable names, string literals)
- **Schema verification**: Check data models, YAML configs, context fields, Parquet columns
- **Documentation audit**: Review all `.md` files including README, plans, templates, api_plan
- **Test verification**: Ensure tests validate UK English schema (e.g. `licence` vs `license`)
- **Comment audit**: Verify all docstrings, inline comments, and code comments use UK English
- **Identifier audit**: Verify all function names, class names, and variable names use UK English

### Out of scope

- Changing external API query parameters (e.g. OpenWeatherMap's `lat`/`lon` must stay as-is)
- Renaming Python stdlib identifiers (`datetime.timezone` is an excepted library identifier)
- Modifying autogenerated files (`uv.lock`)
- Creating new features or functionality

3. **Package names**: `charset_normalizer` in dependencies (vendor package name)
